Telegram AI Agent 入門模板：快速開始

這一段帶你「不靠任何 token」就把程式跑起來、看到真實輸出，最後再說明需要 Telegram / LLM 金鑰才能做的那幾步（會明確標註需金鑰）。

前置需求

  • Python 3.10+（本文用 3.12.3 實測）
  • Git、終端機
  • 想接真實 Telegram / LLM 時，才需要對應帳號與 API key。

第一步：安裝（不需任何 token）

git clone https://github.com/yazelin/telegram-ai-agent-starter.git
cd telegram-ai-agent-starter
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env

成功的話 pip install 最後一行會是 Successfully installed ... fastapi-0.115.6 ... uvicorn-0.34.0 ...，沒有紅色 ERROR。

第二步：啟動服務並做健康檢查（不需任何 token）

uvicorn app.main:app --host 127.0.0.1 --port 8000

啟動成功會看到：

INFO:     Application startup complete.
INFO:     Uvicorn running on http://127.0.0.1:8000 (Press CTRL+C to quit)

另開終端機打健康檢查：

curl http://127.0.0.1:8000/health

真實輸出：

{"ok":true}

這代表服務活著、/health 與 /webhook/telegram 兩個 endpoint 都已掛載。

第三步：用 echo provider 跑一次對話邏輯（不需任何 token）

.env 預設 AI_PROVIDER=echo，純回聲、不需金鑰。把下面存成 repo 外的 /tmp/try_echo.py：

import asyncio
from app.agent import ask_ai
from app.tools import run_tool

async def main():
    print("ask_ai echo:", repr(await ask_ai("hello from a learner")))
    print("run_tool time:", repr(await run_tool("time")))
    print("run_tool help:", repr(await run_tool("help")))

asyncio.run(main())

在 repo 根目錄跑 AI_PROVIDER=echo python /tmp/try_echo.py，真實輸出：

ask_ai echo: 'Echo: hello from a learner'
run_tool time: '2026-06-02T03:30:19+08:00'
run_tool help: 'Try /ask your question or /tool time'

到這裡程式邏輯已完整跑通，完全不需任何外部帳號。注意 echo / claude-cli / gemini-cli 都是純對話，不會呼叫工具；只有 http 會 tool-calling。

AI_PROVIDER 選項

  • echo：純回聲，不需金鑰，不呼叫工具。
  • http：OpenAI-compatible /chat/completions，唯一支援 tool-calling 的模式（需 HTTP_LLM_ENDPOINT / HTTP_LLM_API_KEY / MODEL_NAME）。
  • claude-cli / gemini-cli：本機 CLI 純對話，不呼叫工具。

第四步：接真實 Telegram（需金鑰）

  1. 跟 @BotFather 申請 bot：傳 /newbot 取名，拿到 TELEGRAM_BOT_TOKEN。
  2. 用 @userinfobot 查到自己的數字 user id。
  3. 填進 .env 的 TELEGRAM_BOT_TOKEN 與 ALLOWED_USER_IDS（allow-list，只有列入者能用，其他人收到 Not allowed.）。
  4. 本機用 polling 啟動（不需公開網址）：python -m app.polling。設好 token 後對 bot 傳 /ask hello 會回 Echo: hello。（此步需真實 token，未貼造假輸出。）

第五步：部署後切換 webhook（需金鑰 + 公開 HTTPS）

webhook 需要對外 HTTPS 網址，部署後用 setWebhook 告訴 Telegram，詳見部署筆記。

第一次成功的標準

  • pip install 無 ERROR。
  • curl /health 回 {"ok":true}。
  • echo driver 印出 Echo: ... 與 time 工具的時間字串。
  • TELEGRAM_BOT_TOKEN 在 .env 裡、沒有 commit 到 GitHub。

Telegram AI Agent 入門模板：架構說明

核心檔案

  • app/main.py：FastAPI webhook 入口
  • app/polling.py：本機開發用 getUpdates polling
  • app/telegram.py：解析 Telegram update、權限檢查、送訊息
  • app/agent.py：AI provider adapter，支援 echo / claude-cli / gemini-cli / http
  • app/tools.py：TOOL_SCHEMAS（OpenAI 工具 schema）與 run_tool(name, arguments) dispatch，提供 time / help / add 工具

資料流

  1. Telegram 送訊息進來：webhook（POST /webhook/telegram）或本機 polling（python -m app.polling，getUpdates + offset）。
  2. handle_update 解析 update、做 allow-list 權限檢查。
  3. /tool 指令直接呼叫 run_tool；其餘文字交給 ask_ai 依 AI_PROVIDER 路由。
  4. http 模式會把對話加上 tools=TOOL_SCHEMAS 送出，若回傳 tool_calls 就執行工具、把結果以 role:"tool" 接回去，最多迴圈 4 次直到產生最終文字（其他 provider 為純 chat）。
  5. 用 sendMessage 把回覆送回 Telegram。

設計原則

  • 先讓流程可跑，再做漂亮抽象。
  • token 與 secrets 全部放在環境變數。
  • 每一層保持可以替換：入口、AI provider、資料來源、部署方式。
  • 範例程式刻意保持小，方便你看懂後改成自己的版本。

Telegram AI Agent 入門模板：帶你走一遍

這一段帶你把「一個會自己呼叫工具的 agent」實際跑出來看到。最重要的是中段那一節：用本機模擬完整重現 tool-calling 迴圈。

哪種 provider 會呼叫工具？

  • echo / claude-cli / gemini-cli：純對話，不送 tools=，不會呼叫工具。
  • http：OpenAI-compatible，會把 tools=TOOL_SCHEMAS 一起送出，讓模型自行決定呼叫工具。以下示範針對 http。

重點：完整看一次 tool-calling 迴圈（本機模擬）

我們用本機模擬：用假的 httpx.AsyncClient 取代真網路，讓它第一次回「要呼叫 time 工具」、第二次回最終答案。app/agent.py 的迴圈邏輯完全沒改，所以執行路徑就是真實那一條。以下為本機模擬，非真實外部 LLM 回應：模型回什麼由腳本指定，但「送出去的內容、工具的執行、結果如何接回」全是程式真的跑出來的。

把 mock 腳本（指定模型第一次要求 time、第二次回答）存在 repo 外，在 repo 根目錄跑 PYTHONPATH=. python /tmp/mock_toolloop.py，真實輸出：

--- HTTP POST #1 -> https://mock.local/v1/chat/completions
    messages sent:
       {'role': 'user', 'content': '現在幾點？'}
    tools= sent: yes (time, help)
    >>> run_tool('time', {}) executed -> '2026-06-02T03:30:53+08:00'
--- HTTP POST #2 -> https://mock.local/v1/chat/completions
    messages sent:
       {'role': 'user', 'content': '現在幾點？'}
       {'role': 'assistant', 'content': None, 'tool_calls': [{'id': 'call_001', 'type': 'function', 'function': {'name': 'time', 'arguments': '{}'}}]}
       {'role': 'tool', 'tool_call_id': 'call_001', 'name': 'time', 'content': '2026-06-02T03:30:53+08:00'}
    tools= sent: yes (time, help)
=== FINAL ANSWER ===
現在時間是 2026-06-02T03:30（由 time 工具取得）。

逐格看懂（對照 run_http_agent）：第 1 次 POST 帶 tools= 但模型回的是 tool_calls；程式用 run_tool("time", {}) 真的算出時間；把結果以 role:"tool"（帶相同 tool_call_id）接回；第 2 次 POST 模型才給最終文字。這就是「agent 會自己呼叫工具」的本體：模型決定、程式執行、結果回灌、模型總結（最多 4 次）。

動手練習：自己加一個工具，讓 agent 會呼叫它

目標：新增 add(a, b) 加法工具，並用同一套模擬證明 agent 真的會呼叫它（本文已實跑驗證）。

before：app/tools.py 只有 time / help。after：在 TOOL_SCHEMAS 末尾加 add 的 schema（描述參數 a、b），並在 run_tool 加一條分支：

if name == "add":
    try:
        return str(float(arguments["a"]) + float(arguments["b"]))
    except (KeyError, TypeError, ValueError):
        return "add needs numeric arguments a and b"

先單獨驗證工具本身（不需金鑰），真實輸出：

direct add: '42.0'
add missing: 'add needs numeric arguments a and b'

再用 mock 證明 agent 會自己呼叫 add（本機模擬，非真實外部 LLM 回應），真實輸出：

Tools now exposed to the model: ['time', 'help', 'add']
--- HTTP POST #1
       {'role': 'user', 'content': '19 加 23 是多少？'}
    >>> run_tool('add', {'a': 19, 'b': 23}) -> '42.0'
--- HTTP POST #2
       {'role': 'user', 'content': '19 加 23 是多少？'}
       {'role': 'assistant', 'content': None, 'tool_calls': [{'id': 'call_add_1', 'type': 'function', 'function': {'name': 'add', 'arguments': '{"a": 19, "b": 23}'}}]}
       {'role': 'tool', 'tool_call_id': 'call_add_1', 'name': 'add', 'content': '42.0'}
19 加 23 等於 42（由 add 工具計算）。

第一行證明新工具已送進 tools=、模型看得到它。加工具的完整套路就是：schema 進 TOOL_SCHEMAS + dispatch 進 run_tool，兩處對齊 name 即可。把 add 換成「查庫存」「叫 AGV」「打公司 API」邏輯一樣。

提醒

  • /tool add ... 手動指令目前只會把參數打包成 {"input": ...}，不會自動拆成 a / b。要餵 a / b 走 http provider 讓模型產生 JSON arguments 才自然。
  • name 在 schema 和 run_tool 要一致，否則會落到 Unknown tool:。

Telegram AI Agent 入門模板：部署筆記

部署前檢查

  • 本機流程已經跑通。
  • `.env` 沒有被 commit。
  • README 的啟動指令與實際程式一致。
  • `/health` 或等價檢查 endpoint 可用。
  • 外部服務 token 已放在部署平台 secrets。

啟動指令

uvicorn app.main:app --host 0.0.0.0 --port 8000

設定 webhook

部署到有公開 HTTPS 網址後，告訴 Telegram 把 update 推到 /webhook/telegram：

curl -F "url=https://YOUR_DOMAIN/webhook/telegram" \
  "https://api.telegram.org/bot$TELEGRAM_BOT_TOKEN/setWebhook"

回傳 {"ok":true,...} 即成功。要改回本機 polling 開發，先 deleteWebhook：

curl "https://api.telegram.org/bot$TELEGRAM_BOT_TOKEN/deleteWebhook"

注意：設定 webhook 後不要同時跑 polling，否則會互搶 update。

常見部署選項

  • Render / Railway / Fly.io：適合快速 demo。
  • VPS + Docker / systemd：適合長期自管。
  • 公司內網主機：適合企業內部工具，但要處理網路與權限。
  • NAS / edge gateway：適合工業或內部自動化場景。

部署後驗證


curl http://127.0.0.1:8000/health

接著再測真正的業務流程，不要只看服務有沒有啟動。

實務提醒

部署不是最後一步。正式使用前至少要補：log、錯誤告警、權限控管、備份策略、secret rotation，以及基本監控。

Telegram AI Agent 入門模板：常見問題與踩雷清單

每一條都附真實 / 預期的症狀，方便對照。

1. 不在 ALLOWED_USER_IDS → 收到 Not allowed.

allow-list 非空時，沒列進去的 user id 一律被擋。實測（一個 allowed、一個非 allowed）：

-> chat 500: 'Echo: what time is it'      # 白名單內，正常回覆
-> chat 500: '2026-06-02T03:30:27+08:00'  # /tool time 正常
-> chat 999: 'Not allowed.'               # 不在白名單，被擋

修法：用 @userinfobot 查到正確 id 加進 ALLOWED_USER_IDS。反向陷阱：留空代表不限制任何人，公開部署前一定要填。

2. polling 遇到壞回應 → 已容錯，不會崩

現在 app/polling.py 遇到 429 或非 JSON body 會退避重試。實測（餵 429 再餵非 JSON body）：

[server returned] HTTP 429 (rate limited)
[server returned] HTTP 200 with non-JSON body '<html>not json</html>'
[polling] getUpdates failed: JSONDecodeError('Expecting value: line 1 column 1 (char 0)'); retrying...
[demo result] loop survived both bad responses and kept polling

偶發 retrying 是正常退避；若一直重試，查 token 與到 api.telegram.org 的網路。

3. webhook 沒回應 → 多半是不是 HTTPS / 沒設對

Telegram webhook 只接受公開 HTTPS。先確認 setWebhook 回 {"ok":true}，用 getWebhookInfo 看 last_error_message。同時跑 webhook 和 polling 會互搶 update，切回 polling 前先 deleteWebhook。

4. 選錯 provider → agent 不會呼叫工具

echo / claude-cli / gemini-cli 都是純對話、不送 tools=；只有 http 會 tool-calling。把 .env 改成 AI_PROVIDER=http 並設好 endpoint / key / model。加了新工具卻沒被呼叫？檢查 schema 的 name 和 run_tool 分支是否一致，不一致會掉進 Unknown tool:。

5. token 外洩 / 沒載入

不要 commit TELEGRAM_BOT_TOKEN（.gitignore 已含 .env）。沒載入時 token 會是空字串、呼叫 Telegram API 會 401。

6. 回覆太長被截斷

程式已截到約 3900 字（reply[:3900]），實務上建議在工具 / prompt 端做摘要。

Debug 順序

  1. 服務有沒有啟動（curl /health 是否回 {"ok":true}）。
  2. endpoint / webhook URL 是否正確（getWebhookInfo）。
  3. 環境變數是否載入。
  4. 用 echo provider 排除 LLM 那一側問題。
  5. 看完整錯誤訊息，不要只看最後一行。
  6. 縮到最小可重現案例。

Telegram AI Agent 入門模板：改成你的使用場景

可延伸方向

  • 新增 /tool 指令：在 app/tools.py 加入自己的工具邏輯。
  • 改成公司內部助理：把 API、查詢腳本或資料庫查詢包在工具裡。
  • 加權限：依 user_id / chat_id 控制不同命令。
  • 加紀錄：把問題、回覆、錯誤寫入 SQLite 或外部 logging。

改造原則

  • 一次只改一個層次：先改資料來源，再改 UI，再改部署。
  • 先保留原本可跑的範例，另開 branch 做實驗。
  • 每加一個外部服務，就加一個健康檢查或 smoke test。
  • 先做 PoC，再決定要不要產品化。

適合拿來做課程 / 工作坊的題目

  • 從零跑起這個 starter。
  • 改成自己的真實場景。
  • 加入權限、部署與監控。
  • 現場 debug 學員遇到的問題。
